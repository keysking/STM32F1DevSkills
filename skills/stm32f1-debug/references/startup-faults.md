# 启动失败、HardFault 与复位

先记录故障状态，决定附加还是复位重现，见[GDB](gdb.md)。本页检查按现象选择，不要求逐项修改系统。

## 不进入 main

1. 检查供电、NRST、BOOT0/BOOT1、实际烧录地址和当前 PC。区分在系统 bootloader、应用、异常循环或调试停机。
2. 检查应用向量表前两字：初始 MSP 位于真实 SRAM 范围，Reset_Handler 地址指向正确代码且最低位为 Thumb 标志。主 SRAM 顶端地址可作为初始栈值，不能只用“必须小于顶端”误判。
3. 查 ELF 的 Reset_Handler、SystemInit、C 运行时、main；在阶段边界设断点，区分数据初始化、时钟等待、构造函数和用户代码。
4. 有 bootloader 时同时检查链接起始地址、下载地址、VTOR、跳转协议。没有偏移需求时不修改向量表。

停在时钟错误路径时，核对真实 HSE 类型/频率与板卡，读取 RCC 状态和等待条件。不能因参考工程使用 8 MHz 晶振就认定当前板也如此；需要有界超时，避免 tick 未运行导致 HAL 超时永远不结束。

## HardFault 取证

F1 Cortex-M3 使用基本异常栈帧，无 FPU 扩展帧。尽早暂停并记录当前 PC/LR、MSP/PSP，以及进入异常时的 EXC_RETURN；若已在 C 处理函数中执行多条指令，LR/SP 可能被编译器序言改变，结合反汇编还原，不能直接当入口现场。

在异常入口，EXC_RETURN 位 2 决定原始帧位于 MSP 还是 PSP。基本帧按顺序为 R0、R1、R2、R3、R12、LR、PC、xPSR；xPSR 位 9 指示额外栈对齐填充。确认栈指针在有效 SRAM 且内存可读后再解码，嵌套异常和堆栈损坏要单独处理。

需要 SCB 状态时，可在 GDB 读取这些 Cortex-M3 地址：

```text
x/wx 0xE000ED28
x/wx 0xE000ED2C
x/wx 0xE000ED34
x/wx 0xE000ED38
```

依次为 CFSR、HFSR、MMFAR、BFAR。只有对应 VALID 位成立时使用 fault address；HFSR FORCED 表示升级异常，还要解码 CFSR。状态记录前不写清除。精确总线错误可结合堆栈 PC；非精确错误不能把该 PC 当成唯一故障指令。

用 `info line *<堆栈PC>`、`x/i <地址>` 和反汇编对应源码，检查空/野指针、越界、栈溢出、错误函数指针、除零/未对齐陷阱设置及无效指令。优化可能使回溯不完整；先保留原始故障固件，再用有依据的观测构建复现。

## 反复复位

尽早读取 RCC 复位原因并保存，之后才清除标志。区分上电/掉电、NRST、软件复位、IWDG、WWDG；标志可能累计，不能只看一个位就排除其他原因。

看门狗的 Init 可能已启动；调试暂停是否冻结会改变表现。检查喂狗周期的最坏执行时间、窗口和健康条件，见[看门狗](../../stm32f1-configure/references/watchdogs-power.md)。栈/供电/复位脚异常需相应板端证据，不能仅凭编译结果下结论。

完成时保留故障证据、原因、最小修复和相同条件下复测。更改时钟/中断等生成配置须同步 IOC。
