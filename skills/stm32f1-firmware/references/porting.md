# 应用接入、驱动移植与生成代码维护

先定义输入/输出、时序、资源和错误行为。按需求增加模块，不默认加入 LED、串口输出、RTOS 或硬件改线。

## 模块接入

应用源放入项目维护的目录，通过[CMake 目标](../../stm32f1-build/references/cmake.md)注册。生成器文件只在适当 USER CODE 区加入调用/声明，保留标记，避免把完整业务实现堆入生成文件。没有生成器的工程沿用原初始化和目录。

启动顺序按依赖安排：HAL 与系统时钟、GPIO/DMA/外设初始化、应用资源初始化、开始异步事务/调度。检查每个返回值，错误路径不得继续访问无效句柄。RTOS API 是否可在调度前调用由具体 API 决定。

## 移植检查

| 来源或需求 | 必须适配的内容 |
| --- | --- |
| 其他 STM32 HAL 系列 | GPIO 复用/AFIO、DMA 固定映射、时钟树、IRQ 名称、外设限制和 API 签名 |
| C5 HAL2 | 生命周期、句柄、GPIO 对象和回调；不复制 HAL2 初始化到 F1 |
| SPL/寄存器驱动 | 头文件来源、时钟初始化、引脚 remap、IRQ/状态所有权；不强制迁移整个已有工程 |
| 轮询改 IT/DMA | 缓冲生命周期、完成与错误回调、取消/重启、并发所有权和时限 |
| 裸机改 FreeRTOS | 阻塞点、ISR 交接、锁、任务栈/堆和 tick 单位 |

F1 Cortex-M3 无 FPU，工具链应软浮点；没有数据缓存不表示不需要同步。`volatile` 不能替代临界区、原子性或多任务互斥。共享多字段数据更新应设计一致性协议。

## printf 与输出

构建出现 printf 不表示板上有输出。检查 `_write`、`__io_putchar` 和实际输出后端，按需求实现 UART/SWO 等；不要自行占用用户未分配的串口。日志调用若位于 IRQ 或持锁状态，需避免阻塞和重入。

nano C 库浮点 printf 通常需链接 `-u _printf_float`，先确认需求与 Flash 预算；支持链接并不代表格式参数正确。串口波特率、终端设置和物理波形独立验证。不要为了看到日志启用 semihosting 却遗漏脱离调试器运行条件。

## 重新生成与验收

修改硬件配置同时维护 IOC。生成前保存差异，生成后检查应用文件、USER CODE 区、根 CMake、源列表和链接布局，见[重生成](../../stm32f1-project/references/regenerate.md)。初始化字段变化需重新评估应用约定，例如 PWM ARR 改变、ADC 通道顺序变化。

完成至少包括：本次源已参与构建、错误/超时路径合理、静态资源预算。功能验收按真实负载覆盖正常、边界和失败行为；未做板端测试时明确停留在编译/代码核对阶段。
