# 保存、重新生成与代码保留

只在任务需要把配置落实到源码时生成；纯查询不执行此流程。先检查现有修改并建立可比较的备份/工作副本，明确用户代码与生成代码的所有者，不清空当前工程。

## 修改配置后的流程

1. 回读改动参数及共享资源：旧/新引脚、SWD、DMA、IRQ、时钟结果。
2. `config save`，确认真实 IOC 已更新。
3. 退出本次 CubeMX，在独立进程 `config load "真实 IOC"`，`waitclock 2`，重新查询关键值。
4. 参数符合需求后 `project generate`，必要时 `config save` 保存生成相关状态，再退出。
5. 查看日志、源码与 CMake 差异，构建本次预设。需要板端证明时执行对应测试。

启动命令见[脚本会话](../../stm32f1-env/references/mx-cli.md)。可以使用独立会话完成第 3–4 步，不要求固定拆成更多进程。

## 文件归属

| 区域 | 维护方式 |
| --- | --- |
| CubeMX 管理的 `.c/.h` 普通区 | 在 IOC/生成设置中修改；手改可能被覆盖。 |
| 合法成对的 USER CODE 区 | 按当前 KeepUserCode 设置维护，重生成后比较；不要挪动/重复标记。 |
| 自有 App 等文件 | 放在生成器不管理的位置，通过根 CMake 或自有 include 文件加入。 |
| 根 CMakeLists、预设、工具链 | 当前生成模板一般保留已存在文件，但必须检查差异，特别是换芯片/版本/编译器时。 |
| `cmake/stm32cubemx/CMakeLists.txt` | 生成器维护，易被覆盖；不把应用扩展只写在这里。 |

保留根工具链也意味着换芯片后可能留下旧链接脚本/CPU 选项；“没被覆盖”不代表仍正确。需要重构应用目录时保留调用入口并完成构建。

## 生成失败或设置未生效

- 进程退出 0，但日志有 KO、异常或缺文件：按失败处理，先定位对应命令。
- 新建会话直接 generate 出现 sysmem/syscalls 重复绝对路径：保存后在独立进程加载再生成，检查实际路径和 CMake 源文件列表；不要因此无条件迁移到 Core/Src。
- `SetStructure`、`SetCopyLibrary` 返回 OK，但 IOC 没变化：先核对本版 Usage、保存值和生成结果，不能声称设置已生效。目录布局不是成功构建的充分条件。
- HAL/LL 切换不生效：保存并独立加载，核对驱动类别和所有受影响实例，见[驱动选择](../../stm32f1-firmware/references/hal-ll.md)。
- 禁用模式后仍有引脚、DMA、IRQ：查询残留所有者，仅释放本次确实不再需要的资源。

停止条件是已找到失败步骤或取得所需产物；不循环生成、不通过删库/删源码碰运气。无法由当前 CLI 完成的设置可按实际安装提供的其他原生入口处理，并说明具体受限项。
